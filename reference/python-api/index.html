    Python API Reference¶

    smolclaw exports all core classes from the top-level package:

    from smolclaw import Agent, Gateway, Router, Memory, Scheduler
from smolclaw import AgentConfig, AgentInfo, GatewayConfig, MemoryConfig
from smolclaw import InboundMessage, OutboundMessage, Job
from smolclaw import HookRegistry, HookContext, PreRouteHook, PostRouteHook
from smolclaw import TelegramChannel, WebhookChannel
from smolclaw import create_channel, register_channel, list_channel_types
from smolclaw import FileWatcher
from smolclaw import TracingConfig, configure_tracing, span, TRACING_AVAILABLE

    smolclaw.router.Router ¶

    Routes messages to agents and collects responses.

    Supports pre-route and post-route hooks via a HookRegistry. Hooks are executed in order before and after agent invocation, allowing message transformation, short-circuiting, rate limiting, logging, etc.

    register_agent(agent) ¶

    Register an agent so it can receive routed messages.

    on_response(source, callback) ¶

    Register a callback for outbound messages from a source.

    route(message) async ¶

    Route an inbound message to the correct agent, return response.

    If hooks are registered, pre-route hooks execute first (may modify the message or short-circuit). After the agent responds, post-route hooks execute (may modify the response).

    get_agent(name) ¶

    Look up a registered agent by name, or None if not found.

    smolclaw.memory.Memory ¶

    Agent-namespaced memory backed by SQLite.

    All agents share one memory.db. Each entry is tagged with an agent name. Agents query their own namespace by default, with optional cross-agent search.

    When sqlite-vec is installed and an embed_fn is provided, vector search is available for semantic similarity queries. Otherwise, FTS5/LIKE is used.

    __init__(db_path, agent='shared', embed_fn=None, embed_dim=256) ¶

    Initialize memory for an agent, creating tables if needed.

    Parameters:

    Name Type Description Default
    db_path Path

    Path to the shared SQLite database file.

    		 required
    agent str

    Agent name used to namespace all stored data.

    		 'shared'
    embed_fn EmbedFn | None

    Optional callable that takes text and returns a float vector. When provided with sqlite-vec, enables semantic vector search.

    		 None
    embed_dim int

    Dimensionality of the embedding vectors (default: 256).

    		 256

    add_fact(content, category='general', source='manual') ¶

    Add a fact to this agent's namespace. Embeds for vector search if available.

    search_facts(query, limit=10, cross_agent=False) ¶

    Search facts using best available method (vector > FTS5 > LIKE).

    vector_search_facts(query, limit=10, cross_agent=False) ¶

    Search facts using vector similarity. Returns results with distance scores.

    Requires sqlite-vec and embed_fn. Returns empty list if not available.

    hybrid_search_facts(query, limit=10, cross_agent=False) ¶

    Combine vector + FTS5 results using reciprocal rank fusion.

    Falls back to FTS5-only if vector search is unavailable.

    list_facts(limit=100, category=None) ¶

    List facts for this agent, optionally filtered by category.

    get_fact(fact_id) ¶

    Get a single fact by ID (must belong to this agent).

    Returns the fact as a dict, or None if not found.

    update_fact(fact_id, content=None, category=None) ¶

    Update a fact's content and/or category (must belong to this agent).

    Syncs FTS5 and re-embeds for vector search when content changes. Returns True if the fact was found and updated.

    delete_fact(fact_id) ¶

    Delete a fact by ID (must belong to this agent). Returns True if deleted.

    add_chunk(user_text, assistant_text='', session_id='') ¶

    Store a conversation chunk. Embeds for vector search if available.

    search_chunks(query, limit=10, cross_agent=False) ¶

    Search conversation chunks using FTS5 with BM25 ranking.

    Falls back to LIKE search if FTS5 query fails.

    vector_search_chunks(query, limit=10, cross_agent=False) ¶

    Search chunks using vector similarity. Returns results with distance scores.

    hybrid_search_chunks(query, limit=10, cross_agent=False) ¶

    Combine vector + FTS5 results using reciprocal rank fusion.

    clear() ¶

    Clear all facts and chunks for this agent. Returns counts of deleted rows.

    stats() ¶

    Return memory statistics: fact/chunk counts for this agent and globally.

    Hooks¶

    smolclaw.hooks.HookRegistry ¶

    Registry of pre-route and post-route message hooks.

    Hooks execute in registration order. Pre-route hooks can modify the inbound message or short-circuit routing entirely. Post-route hooks can modify the outbound response.

    Example::

    registry = HookRegistry()

async def log_messages(msg, ctx):
    print(f"[{ctx.agent_name}] {msg.text}")
    return None  # pass through

registry.add_pre_hook("logger", log_messages)

    pre_hook_names property ¶

    List registered pre-route hook names in execution order.

    post_hook_names property ¶

    List registered post-route hook names in execution order.

    stats property ¶

    Summary of registered hooks.

    smolclaw.channel.WebhookChannel ¶

    Bases: Channel

    Outgoing webhook channel — POSTs agent responses to a configured URL.

    Send-only channel for delivering messages to HTTP endpoints (e.g. Slack incoming webhooks, Discord webhooks, custom APIs). Does not receive inbound messages (use the REST API for that).

    Config in agent.yaml::

    channels:
  webhook:
    url: "https://hooks.example.com/endpoint"
    headers:
      X-Custom-Header: "value"

    __init__(agent_name, config, router) ¶

    Initialize the webhook channel with URL and optional headers.

    start() async ¶

    Validate webhook configuration (no persistent connection needed).

    stop() async ¶

    No-op — webhook channel has no persistent connection.

    send(chat_id, text) async ¶

    POST a JSON payload to the configured webhook URL.

    Channel Registry Functions¶

    from smolclaw import register_channel, list_channel_types, create_channel

# Register a custom channel type
register_channel("discord", DiscordChannel)

# List all available channel types (built-in + custom + entry points)
types = list_channel_types()
# {'telegram': TelegramChannel, 'webhook': WebhookChannel, 'discord': DiscordChannel}

# Create a channel instance by type name
channel = create_channel("telegram", agent_name="tars", config=cfg, router=router)
